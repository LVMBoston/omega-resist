# PLAN: Xlsx Share-Intent Export

Status: Proposed (not yet implemented)
Date: 2026-07-07

## Goal
Reflect share-intent data (orange map-marker border) in both xlsx exports (`Tokens` and `Events`) generated by `src/lib/exportCampaignXlsx.ts`.

## Scope
Two workbooks produced from the Campaign Dashboard:
a. Tokens export
b. Events export

## Changes

### 1. Per-token `engagement_state` (none | intent | completed)
a. Match `SamizdatMap` border logic: compute child tokens + view events, classify by child view status.
   - none = no children
   - intent = has children but none viewed (orange border)
   - completed = at least one child viewed (cyan border)
b. Apply to L00 and L01+ tokens on their own children.

### 2. Tokens sheet
a. Add one new column: `engagement_state`.
b. Update `TOKEN_SCHEMA` describing the three states and their mapping to map marker borders.

### 3. New "Campaign Story" summary sheet in BOTH workbooks
a. Reuse `computeCampaignStoryInputs` (already returns `intentCount`).
b. Two-column layout of metrics:
   - Seeds
   - Sprouts
   - Share intent (orange)
   - Completed (cyan)
   - Views
   - Zip codes
   - US states
   - International countries
   - Max chain depth
   - Last share
c. Include narrative text from `formatCampaignStory(...)`.

### 4. Signature change
a. `exportTokensXlsx` and `exportEventsXlsx` need `campaignId` (not just `campaignCode`).
b. Update the two callers in `CampaignDashboard.tsx`.

### 5. Overview narratives
a. Add one line in each export's `NARRATIVE` block noting the Campaign Story tab is included.
b. Note that `engagement_state` mirrors the map marker border color.

## What does not change
- Events sheet row shape
- `computeCampaignStoryInputs` (already returns `intentCount`)
- File naming
- Download flow
- Batching logic
