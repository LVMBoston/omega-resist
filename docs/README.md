# Documentation Directory

This directory contains analysis reports, investigations, and architectural decisions for the Lovable project.

## Purpose

Track conversations, findings, and decisions from AI assistants (Lovable AI and external tools like Codex) to maintain project knowledge and debugging history.

## Directory Structure

```
docs/
├── README.md (this file)
├── investigations/
│   ├── hotspot/           # Hotspot-related investigations
│   ├── virality/          # Virality tracking investigations
│   ├── auth/              # Authentication investigations
│   └── [feature-area]/    # Other feature areas as needed
├── decisions/
│   ├── hotspot/
│   ├── architecture/
│   └── [feature-area]/
├── reports/
│   ├── hotspot/
│   ├── performance/

```

## Naming Convention

### Format
```
[category]/[project-area]/YYYY-MM-DD_specific-topic_investigation-type_author.md
```

### Components
- **Category**: Top-level category (`investigations/`, `decisions/`, `reports/`, `integrations/`)
- **Project Area**: Feature or subsystem (e.g., `hotspot/`, `virality/`, `auth/`)
- **Date**: ISO format (YYYY-MM-DD) - date the investigation/report was created
- **Specific Topic**: Kebab-case descriptor (e.g., `youtube-playback`, `csp-headers`, `click-tracking`)
- **Investigation Type**: Brief descriptor (e.g., `analysis`, `bug-report`, `audit`, `decision`)
- **Author**: Who generated the document
  - `lovable` - Created by Lovable AI during normal development
  - `codex` - Generated by external Codex analysis tool
  - `manual` - Manually written by human developer
  - `combined` - Collaborative document with multiple contributors

### Examples

**Good:**
- `investigations/hotspot/2025-11-01_youtube-playback_codex-analysis.md` - Codex analysis of YouTube hotspot issues
- `decisions/hotspot/2025-11-01_iframe-strategy_architectural-decision_manual.md` - Developer's architecture decision
- `reports/hotspot/2025-11-01_csp-headers_security-audit_lovable.md` - Lovable's CSP security review
- `investigations/virality/2025-11-02_utm-tracking_bug-report_lovable.md` - Virality tracking bug

**Bad:**
- `analysis.md` - Missing all context
- `hotspot/2025-11-01.md` - Missing topic and author
- `2025-11-01_youtube-bug.md` - Missing category and project area
- `investigations/2025-11-01_youtube_analysis.md` - Missing project area

## Authorship Guidelines

### Lovable AI Documents
- Generated during normal chat and development flow
- Include inline code references, file paths, line numbers
- May reference previous conversation context
- Tagged with `_lovable` suffix

### Codex Analysis Documents
- Generated by external Codex tool
- Typically comprehensive codebase analysis
- Focus on architecture, dependencies, security
- Include file trees, component graphs, dependency chains
- Tagged with `_codex` suffix

### Manual Documents
- Written by human developers
- Capture decisions, rationale, trade-offs
- May synthesize findings from multiple AI sources
- Tagged with `_manual` suffix

### Combined Documents
- Start with one author's work, extended by others
- Clearly mark sections with author attribution
- Example format:
  ```markdown
  ## Initial Analysis (Codex - 2025-11-01)
  [content]
  
  ## Follow-up Investigation (Lovable - 2025-11-01)
  [content]
  ```
- Tagged with `_combined` suffix

## Document Structure

Each document should include:

```markdown
# [Title]

**Date:** YYYY-MM-DD  
**Author:** [Lovable AI | Codex | Developer Name]  
**Related Issue/Feature:** [Description or link]  
**Project Area:** [hotspot | virality | auth | etc.]

## Summary
Brief overview of the investigation/decision

## Context
Background information, what triggered this investigation

## Analysis
Detailed findings, code references, data

## Recommendations
Actionable next steps

## References
- Related files
- Related documents (use relative paths)
- External documentation
- Previous investigations
```

## Creating New Project Areas

When starting work on a new feature or subsystem:

1. Create subdirectories across all relevant categories:
   ```bash
   mkdir -p docs/investigations/[new-area]
   mkdir -p docs/decisions/[new-area]
   mkdir -p docs/reports/[new-area]
   ```

2. Use kebab-case for project area names (e.g., `deck-builder`, `qr-generation`)

3. Keep area names consistent across all categories

## Maintenance

- Archive old investigations to `docs/archive/[category]/[project-area]/` after 6 months
- Update this README when adding new document types or categories
- Link related documents using relative paths
- Keep filenames under 80 characters when possible

## Cross-Referencing

When referencing other documents, use relative paths:

```markdown
See also: [Initial Hotspot Analysis](../investigations/hotspot/2025-10-15_click-tracking_bug-report_lovable.md)
```
